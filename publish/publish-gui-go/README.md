# publish-gui-go

`AlyPublish` 发布 GUI 的**主实现**（Go / MyGo native UI）。历史上的 C# / Avalonia 版
`publish-gui-csharp` 仍保留在仓库中，但不再默认构建与发布。两者共用同一套发布包
布局（`payload.json`、Inno Setup 安装器、Linux `install.sh`）与同一组 release 资产名，
配置格式完全一致，替换对使用者透明。

## 发布与替换

Release Build 工作流提供 `gui` 输入，最终生效值由顶层 `env.PUBLISH_GUI` 统一决定：

| 取值 | 行为 |
|---|---|
| `auto`（默认） | 跟随仓库变量 `PUBLISH_GUI`；未设置时为 `go` |
| `go` | 强制用本目录构建 GUI 本体，产出**同名**的 4 个资产 |
| `csharp` | 强制发布历史 Avalonia 版（需要回退时使用） |

优先级：手动显式选 `go` / `csharp` > 仓库变量 `PUBLISH_GUI` > `go`。
`release` 事件没有 inputs，会落到仓库变量。

手动触发：仓库 Actions → Release Build → Run workflow，`gui` 选 `go`；正式发版时
同时填 `version=vX.Y.Z` 并勾选 `upload_to_release`。「一键全部构建」也有同名
`gui` 输入，`auto` 默认跟随仓库变量。产出
`AlyPublish-Setup.exe`、`AlyPublish-win-x64.zip`、`AlyPublish-linux-x64.zip`、
`AlyPublish-linux-arm64.zip` —— 与 C# 版同名，网站下载链接无需改动。两个打包 job
的 payload 铺装、安装器、zip 逻辑完全复用，只是 GUI 二进制的产出步骤二选一。

Go 版已是**默认**实现（含 `release` 事件自动发布）。如需临时切回 C# 历史版，
在仓库 Settings → Secrets and variables → Actions → Variables 设置仓库变量
`PUBLISH_GUI=csharp`，或手动触发 Release Build 时选 `gui=csharp`。
注意 `workflow_dispatch` 的 `default` 只影响手动触发，且只有 `auto` 会读取仓库变量。

替换前提（均已落实）：

- **配置兼容**：`config.json`、`settings.json`、`.updator/shared.json` 的路径与字段
  与 C# 版一致，可无缝接管已有项目书签；文件带 UTF-8 BOM（记事本保存）也能读取，
  与 C# `File.ReadAllText` 行为一致。主题/主题色单独存 `appearance.json`，
  不会被 C# 版切换语言时覆盖。
- **payload 驱动**：读包内 `payload.json` 的 `cli_rid` / `client_rid` /
  `payload_rids` 定位发布 CLI 与更新器，与 C# `PkHelper` 行为一致；开发树没有
  manifest 时回退到本机 rid 候选。
- **包布局**：GUI 本体、安装器、启动器同名同位置，`install.sh` 补齐可执行位。
- **功能对等**：项目书签、添加本地/服务端项目、CLI `config init`、
  `UpdateFolder/client.json`、暂存/取消暂存、发布（流式进度/取消/强制更新）、
  编辑项目与服务端 ignore 同步、版本历史，以及 F5 / Ctrl+Enter / Ctrl+E 快捷键。
  与 C# 版逐项对齐的界面行为：
  - 添加服务端项目为**两步向导**（服务端项目 → 本地目录），含已用服务器地址 chips、
    获取/筛选/空态/错误提示、项目行（名称/标题/ID/版本/强制更新徽标）、
    服务端项目列表、独立「创建项目」子页（标题联动名称、重名校验、强制更新、
    忽略规则建议）、本地目录实时状态（不存在/已初始化/已在列表/可用）与拖放、
    主程序候选自动探测、关闭进程名、四组忽略/不复制规则、校验行与忙碌 Spinner；
  - 添加本地项目在弹窗内填写目录（浏览/拖放/实时状态/preview/显示名）；
  - 项目设置含读取失败横幅、主程序存储路径提示、已用地址 chips、忽略规则建议、
    四组规则编辑、保存忙碌提示与 Enter 提交；
  - 详情页含首次加载遮罩、刷新/暂存/发布忙碌提示、发布按钮与上传进度计数、
    历史「最新」标记、可拖拽分栏；主窗口含搜索无结果「清除搜索」、空列表双入口、
    CLI 横幅「打开 CLI 目录」、状态栏忙碌提示与日志按钮；
  - 弹窗语义：Esc 关闭（向导子页回退一步），点击遮罩不关闭，弹窗内所有控件可点。
- **额外能力**：深浅色主题与主题色、每个项目独立的表单/选择状态、添加服务端项目
  时的高级忽略规则。

## 界面设计

界面按一套小设计系统组织，不是散落的颜色字面量：

- **设计令牌**（`theme.go`）：窗口画布、卡片、输入底色、分隔线、三级文字色，
  以及主色/成功/警告/危险/信息的「主色 + 浅底 + 描边」三件套。浅色与深色各一套，
  主题色（蓝/青/绿/紫/橙/玫红/靛）再派生悬停/按下/浅底，整体写入 MyGo 主题，
  文本框、复选框、表格、滚动条、焦点环等原生控件同步获得同一套配色。
- **控件层**（`ui_kit.go`）：主按钮/次按钮/幽灵按钮/危险按钮/柔和主色按钮，
  各自有悬停、按下、禁用三态（禁用是灰底灰字而非整块变淡）；可关闭标签、
  虚线建议标签、状态标签、计数徽标、图标底色块、卡片与卡片标题、
  对话框外壳（标题块 + 滚动正文 + 不透明底栏）、说明/错误行、忙碌行、空态。
  **图标分两类**：图标按钮（工具条、卡片刷新、文件定位、关闭等）悬停时出现
  底色并加深图标色、带 tooltip；装饰性图标（页头标记、卡片标题前的图标、
  对话框标题图标、空态图标）只是着色，不响应悬停，不会被误认为可点。
- **标签**：网页式圆角标签——浅色底 + 同色描边 + 同色文字，可带图标，
  关闭的「×」悬停时变红，建议标签是虚线框，点击即加入规则。
- **Toast**：右下角卡片式提示，成功/警告/错误各有图标与描边色，可手动关闭，
  4 秒后自动消失（`ui_kit_test.go` 覆盖显示与过期）。
- **布局**：56px 工具条 + 288px 项目侧栏 + 三段式详情（变更 / 发布 / 历史）+
  34px 状态栏；卡片圆角 12、控件圆角 8、8px 间距栅格；对话框统一
  标题/正文/底栏结构与 20px 横向内边距。表格在窄窗口自动收起「服务端大小」列，
  侧栏在窗口变窄时让出空间，最小窗口 1080×640 下所有页面与弹窗仍可用。
- **空间利用**：变更分栏（未暂存/已暂存）与右侧分栏（发布/版本历史）都是
  **定比例、可拖动**的，默认各占一半，比例按项目记住；文件增减或窗口缩放只按
  比例分配，不会自动改变两侧大小，一侧为空时用整块空态填满自己的那一半。
  发布说明固定高度、内容在框内滚动，输入再长的说明也不会挤压版本历史。
  文件表底部有「N 个文件 · 总大小」汇总，行数少时剩余高度显示「刷新可见新文件 /
  发布按顺序上传」的提示；版本历史同样有行数少时的提示与「共 N 个版本」底栏；
  项目侧栏底部固定 CLI 状态、项目数与 Ctrl+F 提示；添加服务端项目的列表是带
  底色/描边/计数的列表面板，创建按钮贴底；其余对话框高度按内容收紧。
- **长列表不压垮页面**：详情页从内容列到分栏、表格逐层 `MinHeight(0)`/定高，
  几百个变更文件或几十条历史记录也只让表格滚动，不会把页头顶到工具栏外面；
  表格滚动条常显，避免“行像被截断”的误解（`TestDetailLargeTablesKeepLayout`
  覆盖 1320×840 与 1720×1100 两种窗口）。
- **变更范围**：变更列表只显示「新增 / 修改」；服务端有、本地没有的文件视为
  服务端保留，不再显示「删除」，发布也不会删除服务端文件（旧版本残留的删除
  暂存条目会被忽略并提示）。
- **操作细节**：Ctrl+F 聚焦搜索、Enter 提交表单、Esc 关闭弹窗（向导子页回退）、
  悬停显示 tooltip（含快捷键）、状态栏按成功/警告/失败变色、忙碌时工具条进度条 +
  状态栏 Spinner。

## 运行依赖

- **Linux**：需要 GTK3（`libgtk-3.so.0`；MyGo 用 purego dlopen 加载）。Go 包带
  `aly-go-gui.marker` 标记（不以点开头，确保打 zip 时不会被排除），`install.sh`
  在缺库时给出安装提示，只提示不阻断；C# 包不带该标记，不会误报。
- **Windows**：D3D11（WARP 回退）；构建带 `-ldflags "-H windowsgui"` 去掉黑色控制台。
- **macOS**：与 C# 版一致 —— 两者目前都只有 Windows / Linux 发布包。

纯 Go、无 cgo、native UI（`ui` 包），不使用 WebView/HTML/JS。配置/日志路径与 C# 版
一致；测试可用 `ALYPUBLISH_CONFIG_DIR` 覆盖，避免污染真实书签。

## 构建

需要 Go 1.27.3（MyGo 0.8.3 要求），并确保 `GOROOT` 指向该工具链。Windows 上如果全局
`GOROOT` 指向 Go 1.10（XP client 的开发环境），先覆盖：

```powershell
$env:GOROOT = 'D:\Install\go1.27.3'   # 本机路径，按实际安装调整
$env:GO111MODULE = 'on'
$env:GOARCH = 'amd64'                  # 全局 GOARCH 可能是 386（XP client），必须覆盖
$env:GOOS = 'windows'
go test ./...
go build -trimpath -ldflags "-H windowsgui" -o build\windows-amd64\AlyPublish.exe .
```

或直接运行 `build.ps1` / `build.sh`（显式设置 GOOS/GOARCH，构建 windows-amd64、
linux-amd64、linux-arm64 三个目标，并执行 fmt/vet/test）。

运行时需要 `aly-publish`：同目录、`publish-cli/<rid>/`、仓库开发路径或
`ALY_PUBLISH` 环境变量；发布包内由 `payload.json` 指定具体 rid。

- 弹窗输入回归（点击弹窗内按钮/规则 chip 有效、遮罩不关闭、Esc 关闭、子页回退）；
- 添加服务端项目向导（两步导航、获取成功/失败/空列表与选择夹取、创建成功/失败、
  初始化及 CLI/UpdateFolder/书签失败原子性、创建校验与标题联动、目录五种状态、
  主程序校验、最小窗口 1080×640 渲染）；
- 添加本地项目与项目设置（目录状态与预览、读取失败横幅、主程序提示、地址 chips、
  保存门禁、保存成功及 CLI/书签失败原子性、最小窗口渲染）；
- 详情页（首次加载遮罩、发布按钮计数与提示、上传进度计数、历史最新标记、分栏夹取、
  忙碌行、中英文与深浅色渲染）；
- CLI 真实 helper-process 契约（`--json`、成功/业务失败/坏输出/空 data/进程失败/取消）、
  参数分批 0/1/200/201/400 与失败停止、暂存/发布/设置保存的成功和失败状态；
- 删除保留策略（GUI 不发布 deleted，旧删除暂存先取消且失败禁止 push）、上传重复终态与
  DONE/FAIL/START 转换计数、`forceKnown` 三态、发布取消/无结果时保留表单；
- `payload.json` 驱动与 manifest 字段一致性、快捷键、`UpdateFolder`、设置隔离、
  BOM 配置读取、配置/初始化/更新器回归测试；
- `UpdateFolder` 尾部分隔符、显式关闭进程名、两件/缺一件复制、半成品自愈、原子写失败
  不残留临时文件；添加本地/移除书签失败原子性，以及项目文件与 `.updator/` 原样保留；
- 偏好与 i18n 回归（`prefs_test.go`）：语言切换写 `settings.json` 并可读回、
  主题/主题色写 `appearance.json` 且不被 settings 重写覆盖、书签移除即时落盘
  （被移除项目的文件与 `.updator/` 原样保留）、zh/en 键集完全一致。

另在 Windows 上以临时配置目录与临时服务端（`server.exe -p … -db <copy>`）做过实机
端到端验证：启动加载书签 → 刷新（status/log） → 全部暂存 → 清空暂存确认框 →
添加服务端项目（获取真实项目列表、创建页、初始化、UpdateFolder、书签） →
项目设置保存并同步服务端 ignore 规则 → 添加本地项目预览并确认 → 发布 V1.0.5
（服务端版本更新、历史出现新记录） → 移除项目 → 深色主题与中英切换。

重做界面后再次实机验收（中文界面）：项目页与侧栏 → 工具条悬停（加深 + tooltip）→
添加服务端项目向导（获取真实项目、选中行白色标签、本地目录步骤）→ 忽略规则页 →
项目设置（四组规则完整可见、底栏不透明）→ 全部暂存 → 填写版本与说明后发布
V1.0.1（历史新增一行、版本徽标更新）→ 切换深色主题。

第三轮再验收：中文项目页确认装饰图标悬停无变化、图标按钮悬停出现底色 + tooltip；
文件表汇总与提示填满面板；添加服务端项目列表为带计数底栏的面板；新增 Toast 与
汇总/提示测试。

第五轮（分栏比例）：实机反馈一侧为空时分栏跳变、发布说明变长会挤压历史。移除
按内容自适应分栏，改为两个分栏都默认 50/50、可拖动、按项目记住比例；发布卡片
改为「表单滚动 + 固定底栏」的定高结构，说明文字长只在输入框内滚动；新增分栏
比例稳定、拖动、长说明不改比例等测试，并在最大化窗口实机复验。

第四轮修复实机反馈：20+ 变更文件、长版本历史与最大化窗口下，内容列没有定高
导致详情页整体上移、页头与标签压在工具栏上；内容列改为定高并给分栏/表格补
`MinHeight(0)`，长列表只滚动不撑破页面。同时历史卡片补上提示与「共 N 个版本」
底栏、空的一侧在空间足够时显示完整空态、表格滚动条常显；新增 1320×840 与
1720×1100 的布局回归测试，并在实机最大化窗口下复验。
