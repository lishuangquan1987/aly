# Aly 项目并行审计报告（15 路子代理扫描）

> 扫描时间：本会话。方法：15 个并行子代理分模块审计 + 父代理直接补审 9 个失败分区并交叉核验关键发现（force_update 重置、退出码恒 0、File.Replace 首写失败、路径穿越等均已对照源码确认）。
> 范围：server（Go+Gin+Ent）、publish-cli（Go cobra）、client/aly-client（Go 1.10/386/XP）、aly-client-sdk（C# net40）、publish-gui（Avalonia）、部署脚本与 CI、跨端契约、文档一致性。
> 未修改任何文件。

**最优先修复（Top 5，会导致真实事故/数据丢失/安全漏洞）**：
1. **server 上传接口 projectName 路径穿越 → 任意文件写入（高危安全漏洞）**
2. **publish-cli 运行期失败退出码恒为 0（CI/GUI 误判成功）**

## 1. server（Go + Gin + Ent + SQLite）

### 🔴 高危

1. **[安全] 上传接口 projectName 路径穿越 → 任意文件写入**
   `server/controllers/file_upload_controller.go:60,69,139-141,163,215-217,224` + `server/internal/service/project_service.go:26-34`
   三个上传接口（upload_file/upload_chunk/upload_chunk_complete）只校验 projectName 非空，**未调用 validateProjectName**。`GetProjectWorkPath` 用 `filepath.Join(exeDir,"data",projectName)` 会 Clean，`projectName=".."` 时 workDir 直接变成 exeDir，后续前缀检查针对已逃逸的 workDir 全部放行 → 可覆盖 aly.db、服务端二进制等任意文件。且 CreateProject 正则 `^[^<>:"/\\|?*]{1,64}$` 允许 "." 和 ".."。
   → 三接口统一调用 validateProjectName；validateProjectName 增加拒绝 "."、".."、尾随点/空格；GetProjectWorkPath 后校验 Clean(workDir) 必须位于 data 目录之下（filepath.Rel 不以 ".." 开头）。

2. **[安全] 全部 API 无鉴权（供应链投毒）**
   `server/routers/routers.go:9-37` — 任何人可 create_project/upload_file 覆盖客户端下载的二进制，且客户端校验用的 SHA-256 也来自同一服务器。
   → 至少加共享 token 头或 Basic 认证，或限制内网绑定 + TLS。

3. **[安全] download_file 无项目归属校验 + 泄露绝对路径**
   `server/controllers/file_download_controller.go:50-69` + `server/internal/service/file_cache.go:187-190`
   仅校验路径字符串前缀在 dataDir 下，无项目归属、不校验项目是否删除；get_all_files 返回 FileAbsolutePath 泄露服务器绝对路径 → 跨项目任意读取/目录枚举。
   → 改为 projectName+relativePath 参数由服务端拼接并做归属校验；FileInfo 只返回相对路径。

4. **[安全] 分片上传不校验项目存在 + TotalChunks 无上限（DoS）**
   `server/controllers/file_upload_controller.go:147-150,247-255` — 可声明 10 亿分片填满磁盘；Complete 对 TotalChunks<=0 时不循环 → 合并出 0 字节正式文件；上传前不校验项目存在即自动建目录。
   → 限制 TotalChunks 数量（如 ≤10000）并校验 >0；上传前先查库确认项目存在。

### 🟠 中等

5. **[并发] 分片合并并发损坏** — `.merging` 固定文件名，两个并发 Complete 同时 os.Create 同一文件交错写入损坏；UploadChunk 与 Complete 无互斥。→ 按 (project,file) 加 sync.Mutex/单飞锁，或临时文件名带唯一后缀再原子 rename。
6. **[数据] 软删除失效** — `project_service.go:152` GetProjectByName 缺 IsDeletedEQ(false)；`project_service.go:140` GetProjectChangeLogs 也未过滤。删除项目仍可查/下载。→ 补过滤，明确"删除项目名可否复用 + 文件是否清理"语义。
7. **[数据] PublishVersion 无重复版本检测 / 版本无规范化** — `project_service.go:160-199` 同版本可重复发布；版本前缀不统一（DefaultVersion "V1.0.0" 带 V vs publish-cli 按用户输入存）；timeStr 为空仍入库。
8. **[数据] 文件缓存指纹陈旧** — `file_cache.go:30-35,200-210` 仅 relPath+size+mtime，同长度覆盖+mtime 还原时返回陈旧哈希，客户端跳过该文件导致更新丢失；测试把该陈旧行为固化为断言。→ 指纹加 ctime/inode 或内容采样。
9. **[数据] UploadFile 非原子写 + 缓存投毒** — `file_upload_controller.go:99-107` SaveUploadedFile 先 truncate 再 copy，失败留下截断文件且 mtime/size 已变 → 重建缓存把损坏文件哈希下发给客户端。→ 临时文件+os.Rename 原子替换，成功后才失效缓存。
10. **[数据] IsUploadTempPath 误伤合法文件** — `file_cache.go:218-225` 按路径段 `.chunks`/`.merging` 后缀判断，项目内合法同名文件（如 data.chunks）上传后永不出现在文件列表。→ 临时文件放项目树外专用目录。
11. **[资源] 无文件删除接口** — `routers.go:29-36` 发布删除的文件服务端/客户端永不清理；get_all_files 返回历史并集而非版本清单。→ 增加 delete_file 接口 + 版本 manifest。
12. **[资源] `.chunks` 目录永久累积** — `file_upload_controller.go:318` RemoveAll 错误被忽略。→ 检查错误并记录日志/定期清理。

### 🟡 低 / 改进

- `main.go:48` WriteTimeout=60s 全局生效，慢速网络下载大文件易被切断。
- download 错误响应格式与其他控制器不一致（404 空 body vs 200+isSuccess=false；客户端只认 200）。
- `file_download_controller.go:31` `projectResult.Data.(*ent.Project)` 无 ok 断言可 panic。
- `project_service.go:89-98` 注释称 ent Save 无法查影响行数，实为不实（Save 返回 (int,error)）。
- `project_controller.go:30-36` 保留名 map 每次调用重建。
- `project_service.go:201-212` DeleteProject 只软删 DB 不删 data 目录 → 磁盘泄漏。
- `file_cache.go:175-197` 每文件分别 open 两次算 md5 和 sha256 → 一次读取双哈希。
- `file_upload_controller.go:199` 每个分片上传都失效缓存 → 合并完成后失效一次。
- `main.go:53-58` ListenAndServe goroutine 内 log.Fatalf 跳过 db 优雅关闭。
- 大量错误路径无日志，排障困难。

## 2. publish-cli（Go cobra）

### 🔴 高危

1. **[bug] 所有命令运行期失败退出码为 0**
   `main.go:10-12` — 全部 Run 处理器失败时只 outputResult(false,...) 后 return，Execute() 返回 nil，进程以 0 退出。CI/GUI 会把失败当成功。
   → 改 RunE 返回 error，或设全局失败标记由 main 非 0 退出。

2. **[bug] 每次成功 push 无条件把服务端 force_update 重置为 false**
   `push.go:222` — setProjectForceUpdate(cfg, pushSetForceUpdate) 总是执行，默认 false 也调用 SetProjectForceUpdate(name,false)，静默覆盖管理员之前的强制更新设置（已对照 push.go:180-191 确认）。
   → 仅当 --set-force-update 显式指定时调用（三态 flag）。

3. **[bug] config init 必填校验失效**
   `config.go:29` — MarkFlagRequired("project") 针对 RootCmd 持久化 flag 不在本地 FlagSet，pflag 报错被忽略；不带 --project 也能写出空 project_name。
   → 在 runConfigInit 内校验非空或改为本地 flag。

### 🟠 中等

4. **[bug] JSON 失败流结束行误报成功** — `push.go:147-151,162-166` + `root.go:179-194` 失败路径仍调用 printProgressDone() 输出 isSuccess:true 结束行。→ 结束行携带真实状态。
5. **[bug] `--limit` 负数导致 make panic** — `log.go:44` `make([]ProjectChangeLog, -5)` 崩溃。→ clamp 到 ≥0。
6. **[bug] 超时永不重试（大小写）** — `client.go:206` strings.Contains(msg,"timeout") 大小写敏感，Go 超时错误是 "Client.Timeout"（大写 T）。→ 小写化或加 "deadline exceeded"。
7. **[bug] 用户路径可越出项目目录** — `add.go:92 / staging.go:94 / push.go:116` `../x` 或绝对路径经 Join 逃逸项目根（服务端会拒，但 add 阶段应校验）。→ 校验 Clean 后路径在项目根内。
8. **[bug] "deleted" 文件永远无法推送** — `add.go:68-72 + status.go:91-99` add --all 只暂存 new/modified，客户端无删除 API、服务端无删除文件路由 → 服务端残留过期文件。
9. **[bug] 版本号零校验** — `push.go:27,33` --version "" 能通过 cobra 必填（按 changed 判定），无格式/重复校验；空版本在全部上传后才被服务端拒绝。→ 上传前客户端校验 + 服务端重复检查。

### 🟡 低 / 改进

- `--json --dry-run` 把人类文本混入 stdout JSON 流。
- project delete / reset --all 无确认。
- log 缺 requireProject。
- config get 未知 key 返回成功+空串；set-array 不校验 add/remove/clear 选一。
- project info 拉全量再过滤（get_project_by_name 端点未用）。
- chunkSize 注释 "50 KiB" 与实际 1MiB 不符；直接上传无重试（分片有 5 次）；客户端未镜像服务端 1GB 上限。
- 版本创建失败留孤儿文件；staging.Clear 失败后重试产生重复版本。
- diff --file 无匹配静默成功；project update 强制 --title；"已添加%d" 缺空格。
- 各命令缺 Long/Example 帮助文档。
- 未发现资源泄漏（Close/临时文件清理到位）。✅

## 3. client/aly-client（Go 1.10 / 386 / XP）— 质量最高

**结论**：整体质量非常高，事务/原子写/崩溃恢复/锁/进程保护设计严谨，测试覆盖好（15 个测试文件）。已逐个通读 main.go、全部 cmd 非测试文件、http_client、config、version、dto、util 全部文件。**未发现高危 bug**。

### 🟠 中等

1. **[设计] 全系统句柄枚举作最后手段代价高** — `handle_scan.go` 深扫 10s-60s 级，虽有 killedPids/deepPaths 去重（common.go:298-314）与"第 3 轮起深扫"策略，但对超大目录（几十万文件）RM 注册路径数也可能超大（process_restartmanager.go:28 rmBatchSize=400 分批）。→ 已合理，可考虑给深扫加时间上限。
2. **[健壮性] 32 位客户端无法读取 64 位进程 PEB** — `process.go:272-274` CWD 探测对 64 位原生进程盲区，注释已明示由重试兜底。→ 已知限制，可考虑提升为 64 位构建或保留兜底。

### 🟡 低 / 改进

- `http_client.go:19` 全局 300s Timeout，超大文件 + 慢速网络仍可能切断；DisableKeepAlives 每次建连（XP 兼容正确选择，但性能可接受）。
- `common.go:296` forceKillWait=5s 固定，慢速杀进程场景可调。
- `config/config.go:159-208` ShouldSkipFolder 的 matchPathPattern 支持 `**`，但 publish-cli scanner 的 isSubPath（scanner.go:247-254）只做前缀匹配，两端 ignore 语义可能不一致（跨端契约项，见 §7）。
- 版本比较 compareVersion（common.go:235-258）按段数值比较 + stripVPrefix，正确；但非数字段按 0 处理，如 "1.0-beta" 与 "1.0" 相等，预发布版本语义需注意。

**亮点**（值得肯定）：FilterKillablePIDs 白名单（process.go:528-594）系统关键进程保护，直接杜绝此前真实事故（误触发 Windows 关机）；explorer 只发 WM_CLOSE 且限定 CabinetWClass/ExploreWClass（process.go:661-694）；锁 TTL+token+IsProcessAlive 双保险（lock.go）；version.json 原子写 + crash recovery 全覆盖（apply_update.go 四种现场分支）；download 原子写 .part+rename+MD5/SHA256 双校验；Go 1.10 兼容细节到位（ioutil.TempFile 无 "*" 占位符、LazyDLL Addr()==0 探测 XP 缺失 API）。

## 4. aly-client-sdk（C# net40 + netstandard2.0）

### 🔴 高危

1. **[bug] DownloadUpdateAsync 死循环 + 永久阻塞**
   `AlyApi.cs:47,51,53-55` — process.Exited 事件未设 EnableRaisingEvents=true，永不触发，内部 cts 永不被取消；aly-client.exe 异常退出（未输出收尾 JSON 行）时 ReadLine 返回 null 后 while(!cts.IsCancellationRequested) 空转 → 100% CPU 死循环，Task 永不完成，AlyUpdateClient 主循环 .Result 永久阻塞（AlyUpdateClient.cs:199）。
   → 启动前设 process.EnableRaisingEvents=true；循环内加 HasExited 检查或 ReadLineAsync+超时。

2. **[并发] Cancel()/Dispose() 无法中断进行中的下载与确认回调**
   `AlyUpdateClient.cs:66-69,156-161,195-199` — 结合第 1 条，下载卡死后整个客户端永远无法停止；Dispose 不 Join 后台任务。
   → CancellationToken 贯穿传入 AlyApi 各方法；Dispose 时 Kill 子进程并 Join。

3. **[bug] .targets 版本占位符使首次构建必失败**
   `AlyClient.CSharpSDK.targets:13-14,22-31` — AlyClientVersion 默认值为字面量 ALY_CLIENT_VERSION_PLACEHOLDER 且从未替换，首次构建（无缓存 aly-client.exe）时下载 URL 404 → Exec 失败 → 消费者构建直接失败。
   → 设真实默认版本号或缺失时清晰报错。

### 🟠 中等

4. **[bug] RunAsync<T> 无整体超时** — `AlyApi.cs:125-183` Task.WaitAll 在子进程挂起时永久阻塞；WaitForExit(30000) 在其后才执行，进程未退出时访问 ExitCode 抛 InvalidOperationException。→ 先 WaitForExit(超时) 再读流。
5. **[并发] 进度回调跨线程 + 异常可中止下载** — `AlyApi.cs:72,80-83` 回调抛异常被外层 catch 捕获导致整个下载误报 NG；WPF/WinForms 直接访问控件跨线程异常。→ 回调 try/catch 隔离或捕获 SynchronizationContext。
6. **[bug] 真实下载失败被静默吞掉** — `AlyUpdateClient.cs:200-216` 非 "already at latest version" 失败不调 OnError、不复位状态。→ 失败分支调 OnError(msg)。
7. **[bug] selfCheckUpdateResult.Data 未判空** — `AlyUpdateClient.cs:54-62,56-57` Data 为 null 时 NRE 形成未观察任务异常；.NET 4.0 未观察 Task 异常可能终止进程，IsRunning 永久 true。
8. **[规范] 确认回调依赖宿主同步阻塞** — `AlyUpdateClient.cs:189,224` 回调不阻塞则 SDK 直接继续，绕过确认；回调永久阻塞时 Cancel 无法打断。→ TaskCompletionSource 显式确认 API。
9. **[规范] ApplyUpdateAsync fire-and-forget 丢失错误** — `AlyApi.cs:191-211` apply_update 失败（锁冲突等）永远不可见，MainLoop 视应用总成功。
10. **[兼容] LangVersion 未固定** — `AlyClient.CSharpSDK.csproj:3-11` 代码用 C#6 插值（AlyApi.cs:95,113）与 C#7 表达式体（AlyUpdateClient.cs:42-43），换旧编译器/旧 MSBuild 即失败。→ 显式 <LangVersion>。

### 🟡 低 / 改进

- UpdateSelf 与主循环派生进程并发争用更新器文件（仅重试 3×1s）；File.Replace 非 Windows 回退删除+改名非原子。
- IsRunning 未 volatile、UpdatorExePath 读写无锁。
- DownloadProgressData.FileSize 用 double 对应 Go int64（>2^53 精度丢失，实际无影响）。
- .targets 自动生成含占位符 YourApp.exe 的 client.json；Invoke-WebRequest 需 PowerShell 3+（XP/Win7 PS2 失败）。
- README 说 net40 用 await 需自备 Microsoft.Bcl.Async（SDK 未引入）。
- 未封装 check_diff；全部方法无 CancellationToken。
- 构造函数即启动后台任务，宿主订阅事件前可能已触发。
- AlyClientStatus 枚举与 Go version.json 状态无映射。

## 5. publish-gui（Avalonia 12.1.1 + MVVM）

### 🔴 高危

1. **[bug] ConfigService.WriteAllTextAtomic 首写必失败（数据丢失/更新链路静默失效）**
   `Services/ConfigService.cs:193-198` — File.Replace(tmp, path, null) 目标不存在时抛 FileNotFoundException（已实测复现）。后果：(1) 首次保存 config.json（新机器添加第一个项目）永远失败、项目列表不落盘；(2) CreateUpdateFolder 写全新的 client.json 永远失败 → aly-client.exe 拿不到 main_exe_relative_path，整条更新链路静默失效。
   → 改用 File.Move(tmp, path, overwrite: true)，或 Replace 抛 FileNotFoundException 时回退 File.Move，并清理失败残留 .tmp。

2. **[bug] CliService.FindCliDefault 开发路径拼错**
   `Services/CliService.cs:41` — 从 bin/Debug/net8.0 只上溯 4 层拼出 src/publish-cli（不存在）；publish-cli 是 publish-gui 的兄弟目录，需上溯 6 层（对照 ConfigService.cs:215 用了正确的 7 层）。当前仅靠 aly-publish.exe 被手工复制到输出目录才 Found。

### 🟠 中等

3. **[bug] 编辑 ignore 列表会静默重置服务端 force_update** — `ViewModels/EditProjectDialogViewModel.cs:540-541` SyncIgnoreToServerAsync 硬编码 forceUpdate:false 调 ProjectUpdateAsync。→ 改传 serverProject.IsForceUpdate。
4. **[资源] 无窗口关闭清理 / 无取消链路** — MainWindowViewModel 无 Closing 钩子、ProcessService 无 CancellationToken；push（300s）/status（30s）子进程在关窗后仍运行，可能留孤儿进程继续上传。→ 关窗时统一 Cancel + Kill(true)；CancellationToken 透传到 WaitForExitAsync。

### 🟡 低 / 改进

- push 超时硬编码 300000ms（5 分钟）；status 默认 30s 对大项目易超时。
- GetRelativePath 跨盘符返回 file:/// 绝对 URI（C:→D:）→ client.json 无效路径。
