# CI 收尾：闭环到全绿（2026-11-11 下午）

> 触发：用户反馈「还是失败」，要求自己爬、改、推、查，直到完全没问题。本轮拿到了**真实 job 日志**，
> 定位到真正的根因，改掉后**在 CI 上跑通**。

## 一、怎么拿到真实报错

Actions 页面是 JS 渲染，本地 `gh` 缺失，但有 curl（`C:\Windows\System32\curl.exe`）。用 token 认证后：

```powershell
curl -sL -H "Authorization: Bearer $env:GITHUB_TOKEN" `
  https://api.github.com/repos/<owner>/<repo>/actions/runs/<runId>/logs -o logs.zip
tar -xf logs.zip -C <dir>      # 日志是 per-job 的 .txt
```

认证要点：**必须走 Authorization 头**（query 里的 `access_token` 会被 400 拒），日志接口返回 302 到
`results-receiver.actions...`，要 `-L` 跟随；zip 用系统 `tar` 解即可（本机没有 `unzip`、Python 也没有 `ziplib`）。

## 二、真实根因（来自 job 日志）

```
##[group]Run publish/publish-gui-csharp/installer/stage-payload.ps1 -Staging publish/publish-gui-csharp/artifacts/staging -App publish/publish-gui-csharp/artifacts/app -Manifest payload.json -AssetCli windows-amd64 -AssetUp windows-x86
=== stage payload ===
manifest=payload.json asset_cli=windows-amd64 asset_up=windows-x86 local=False
Exception: publish/publish-gui-csharp/installer/stage-payload.ps1:57
  57 |         throw ("payload source missing: {0}" -f $direct)
     | payload source missing:
     | D:\a\aly\aly\publish\publish-gui-csharp\artifacts\staging\aly-publish-windows-amd64\aly-publish-windows-amd64.exe
```

结论：**下载的 artifact 并不落在「staging/<资产名>/…」这层子目录里**（脚本的直取与递归兜底都没命中），
三个 GUI job 因此在同一步失败；而它们**前面**所有步骤——`dotnet test`、Windows 单文件发布、
Linux 跨平台发布、五个 artifact 下载——在日志里都是 success。

## 三、修法（已推）

把铺装从 `.ps1` 文件改成 **release 工作流里的内联 pwsh 步骤**，并对每个 payload 文件做
「直取 → 平铺 → 递归找同名文件（只认 `Length > 0` 的真文件）」三形态命中，缺一即 `throw`，
并把结果树打进 CI 注解。这一版对**任何**下载形态都成立，所以不再依赖对布局的假设。
（同一提交里删除了 `stage-payload.ps1`，本机开发路径改由 `publish/deploy-publish.bat` 用同一套文件名直接 copy。）

## 五、待用户决定的一点

`workflow_dispatch` 触发时 `upload_to_release` 默认为 false，所以上面的 release 构建**只构建、不上传**；
要真的上传资产，得走 release 事件（dispatch 的 body 只允许 `ref` 这类键，塞不进 `upload_to_release`）。

## 六、最后一环：发布资产只留三类（v0.1.10 实测）

v0.1.9 的资产页有 30 个资产，其中 9 个是**不该再单独发布**的：`aly-client.exe`、`aly-client-ui.exe`、
`aly-client-linux-*`、`aly-client-ui-linux-*`、`aly-publish-windows-amd64.exe`、`aly-publish-linux-*`。
根因在 `upload-release-assets`：那一步用 `download-artifact@v4` **批量**下载整个 run 的产物，
再 `find artifacts -type f` 全量上传——于是已经打进安装包的客户端与发布 CLI 又漏回了 Release 页。

修法（提交 `81f5d6b`）：批量下载后加一道**白名单**，只留三类，其余就地删除并打印保留清单：

```yaml
      - name: Keep only the assets this release ships
        run: |
          before=$(find artifacts -type f | wc -l)
          find artifacts -type f ! \( \
              -name 'AlyPublish-*' -o \
              -name 'aly-server-*' -o \
              -name 'AlyClient*' \
            \) -print -delete
          after=$(find artifacts -type f | wc -l)
          printf 'Assets kept: %s of %s\n' "$after" "$before"
          find artifacts -type f | sort
```

闭环证据（`v0.1.10`，release 事件，target master `81f5d6b`）：

| 项 | 结果 |
| --- | --- |
| Release Build run `42981795285`（release 事件） | **completed success** |
| release `v0.1.10` 资产 | **21 个** |
| GUI 安装包/便携包 | `AlyPublish-Setup.exe`、`AlyPublish-win-x64.zip`、`AlyPublish-linux-x64.zip`、`AlyPublish-linux-arm64.zip` |
| 服务端单文件 | `aly-server-{windows-amd64.exe,linux-amd64,linux-arm64,darwin-amd64,darwin-arm64}` |
| 语言 SDK | `AlyClient.*-0.1.10.zip` ×11 + `AlyClient.CSharpSDK.0.1.10.nupkg` |
| 单独的 `aly-client*` / `aly-publish-*` | **0 个**（符合「只装一个安装包」的发布契约） |

这样需求①的发布侧才算真正落到 Release 页上：客户端与发布 CLI 只随 `AlyPublish` 安装包发布，
由包内 `payload.json` 索引，GUI 运行时按当前系统自动取用。

## 七、宿主生命周期：「宿主退出，更新器/UI 也跟着退」（同日晚）

需求与设计（三处边界都经用户确认）：

- 宿主 = **拉起了本进程的父进程**（`HostProcessID()`：Windows 走 Toolhelp32 快照的 `ParentProcessID`，Unix 用 `os.Getppid()`）；
- 例外**取或**：命令级（当前命令就是 `apply_update`）或状态级（`version.json` 的 `version_status == applying`，覆盖崩溃恢复窗口）；
- 退出**优雅收尾**：先写日志/stderr 诊断，再 `os.Exit(0)`；更新锁不显式释放——残留锁按「持有者进程已退出」判陈旧（`cmd/lock.go` 的 `cleanStaleLock`）。

落点：[spec/host-contract.md](/spec/host-contract.md) 新增 §15（规范性）；
`client/aly-client/util/host.go`（纯决策 `ShouldExitOnHostGone` + 守护协程 `WatchHostExit`）+ 两个平台实现文件 +
`main.go` 接线；`aly-client-winui/app/host.go`（用 vendored `syscall` 探活）与 `aly-client-linuxui/host.go`（用 `/proc/<pid>`）；
网站 [client/index.md](/website/docs/client/index.md) 同步一节。

CI 闭环（`release.yml` dispatch，提交 `e6012fe`）：run `42998596593` **全绿**——
Windows XP 32 位的 `aly-client` 与 `aly-client-ui`（含 PE 头 + manifest 的 XP 兼容性校验）、
Linux 的 `aly-client` 与 `aly-client-ui`（含配置/自更新单测与 UI 原生构建）、以及三个 GUI 安装包全部 success。
