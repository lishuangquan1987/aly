# Data Models

The server has two kinds of "model" with different naming styles; mixing them up is the most common source of integration bugs:

| Source | Purpose | Naming style | Example |
| --- | --- | --- | --- |
| Hand-written DTOs in controllers | Request bodies (POST JSON / multipart) | camelCase | `isForceUpdate`, `ignoreFolders` |
| ent-generated entities | Responses (projects, changelogs) | snake_case | `force_update`, `ignore_folders` |
| `server/models` structs | Responses (file list, system info) | camelCase | `fileAbsolutePath`, `goARCH` |

## Naming conventions

### Requests: camelCase

| Endpoint | Fields |
| --- | --- |
| `create_project` / `update_project` | `name`, `title`, `isForceUpdate`, `ignoreFolders`, `ignoreFiles` |
| `set_force_update` | `projectName`, `forceUpdate` |
| `publish_version` | `projectName`, `version`, `logs`, `time`, `afterApplyUpdateScript` |
| `upload_file` / `upload_chunk` | `projectName`, `relativeFileName` (+ `chunkIndex`, `totalChunks`) |
| `upload_chunk_complete` | `projectName`, `relativeFileName`, `totalChunks` |
| `download_file` | Query parameter `path` |

### Responses: two styles coexist

- `Project`, `ProjectChangeLog`: generated by ent, snake_case (`force_update`, `after_apply_update_script`).
- `FileInfo`, `ServerOSInfo`: defined in `server/models/models.go`, camelCase (`fileAbsolutePath`, `goARCH`).

Field mapping:

| Meaning | Request field | Response field |
| --- | --- | --- |
| Force update | `isForceUpdate` / `forceUpdate` | `force_update` |
| Ignored folders | `ignoreFolders` | `ignore_folders` |
| Ignored files | `ignoreFiles` | `ignore_files` |
| Post-update script | `afterApplyUpdateScript` | `after_apply_update_script` |
| Project ID | — | `project_id` |
| Deletion flag | — | `is_deleted` |

### `omitempty`: zero-value fields are omitted

All business-field JSON tags on ent entities include `omitempty` (only `edges` is the exception; it always outputs `{}`), so a response **may omit certain keys** rather than giving `false` / `[]`:

| Field | Omitted when |
| --- | --- |
| `force_update` | Value is `false` |
| `is_deleted` | Value is `false` |
| `ignore_folders` | Empty array |
| `ignore_files` | Empty array |
| `after_apply_update_script` | Empty string |
| `id` / `project_id` | Value is `0` (does not happen with normal data) |

`created_at` is a `time.Time` struct; `omitempty` has no effect on it, so it is always present.

Deserializers must treat missing keys as zero values (aly-publish's `models.Project` is defined exactly that way). Do not use "whether the key exists" to determine business state.

## Project

Corresponds to `server/ent/schema/project.go`, table name `projects`.

| JSON field | Type | Database column | Description |
| --- | --- | --- | --- |
| `id` | int | `id` | Auto-increment primary key |
| `name` | string | `name` | Project name, **unique**; it is also the directory name under `data/`, and cannot be changed after creation |
| `title` | string | `title` | Project title, for display |
| `version` | string | `version` | Current version number; `V1.0.0` at creation, updated by `publish_version` |
| `force_update` | bool | `force_update` | Whether to force the update; omitted when `false` |
| `ignore_folders` | string[] | `ignore_folders` | Ignored folders (JSON array), matched by prefix |
| `ignore_files` | string[] | `ignore_files` | Ignored files (JSON array), glob supported |
| `created_at` | string | `created_at` | Creation time, defaults to `time.Now()` |
| `is_deleted` | bool | `is_deleted` | Soft-delete flag, defaults to `false` |
| `edges` | object | — | Association placeholder, always `{}`; `change_logs` is not preloaded |

Relation: `projects` 1—N `project_change_logs` (through `project_id`).

`name`'s unique constraint is enforced at the database level, so soft-deleted projects still occupy the name: after deletion the same name cannot be recreated.

### Example

```json
{
  "id": 2,
  "name": "demo2",
  "title": "Demo2",
  "version": "V1.0.0",
  "force_update": true,
  "ignore_folders": ["logs"],
  "ignore_files": ["*.log"],
  "created_at": "2026-11-10T10:59:35.6878741+08:00",
  "edges": {}
}
```

## ProjectChangeLog

Corresponds to `server/ent/schema/projectchangelog.go`, table name `project_change_logs`.

| JSON field | Type | Database column | Description |
| --- | --- | --- | --- |
| `id` | int | `id` | Auto-increment primary key; the changelog endpoint sorts by it descending |
| `project_id` | int | `project_id` | Owning project ID; the foreign key points to `projects.id`, `ON DELETE SET NULL` |
| `version` | string | `version` | Version number of this release |
| `logs` | string[] | `logs` | Change descriptions (JSON array) |
| `time` | string | `time` | Time string supplied by the publisher; the server only validates the format and does not convert time zones |
| `created_at` | string | `created_at` | Time written by the server |
| `is_deleted` | bool | `is_deleted` | Soft-delete flag, defaults to `false`; changelog queries filter on it |
| `after_apply_update_script` | string | `after_apply_update_script` | Script to run after the update, relative to the application directory; omitted when an empty string |
| `edges` | object | — | Always `{}`; `project` is not preloaded |

Creating a project automatically writes one entry: `version = V1.0.0`, `logs = ["第一次创建"]`, with `time` set to the server's current time.

### Example

```json
{
  "id": 3,
  "project_id": 1,
  "version": "1.0.1",
  "logs": ["Fix A", "Fix B"],
  "time": "2026-11-10 11:00:00",
  "created_at": "2026-11-10T10:59:44.0995513+08:00",
  "after_apply_update_script": "run.bat",
  "edges": {}
}
```

`project_id` being `0` / missing can only come from an old-database migration leftover (the old `project_change_logs` column was not fully migrated) or from direct database edits; both normal write paths (`create_project`, `publish_version`) always set it.

## FileInfo

Corresponds to `FileInfo` in `server/models/models.go`, returned by `get_all_files`, and not persisted.

| JSON field | Type | Description |
| --- | --- | --- |
| `fileAbsolutePath` | string | Absolute path on the server; the `path` for `download_file` must use it |
| `fileRelativePath` | string | Path relative to the project directory, `/`-separated; also the sort key |
| `lastUpdateTime` | string | File mtime |
| `fileSize` | int64 | Size in bytes |
| `md5` | string | MD5, lowercase hexadecimal (32 characters) |
| `sha256` | string | SHA-256, lowercase hexadecimal (64 characters) |

The list is sorted ascending by `fileRelativePath` and has already filtered upload intermediates, the release manifest, and project ignore rules.

### Example

```json
{
  "fileAbsolutePath": "/opt/aly/data/demo/app.exe",
  "fileRelativePath": "app.exe",
  "lastUpdateTime": "2026-11-10T11:00:09.4428015+08:00",
  "fileSize": 1500,
  "md5": "2e3587c7179025e801964d9babf8c70e",
  "sha256": "e83835331f9b903cb728137f30b1bb1d83d3751ed561801e79555cfaca4eeb45"
}
```

Path separators vary with the server OS (Windows uses `\`, Linux/macOS use `/`); this is an absolute path for the server itself to parse, and clients must not rewrite it.

## ServerOSInfo

Corresponds to `ServerOSInfo` in `server/models/models.go`, returned by `get_project_os_info` and `server/info`, always a **single-element array**.

| JSON field | Type | Description |
| --- | --- | --- |
| `os` | string | `runtime.GOOS`: `windows` / `linux` / `darwin` |
| `platform` | string | Distribution/platform description; empty string when unavailable |
| `goARCH` | string | `runtime.GOARCH`: `amd64` / `arm64` / `386` |
| `version` | string | Go runtime version, e.g. `go1.25.0` |
| `numCPU` | int | Number of logical CPUs |
| `cpuName` | string | CPU model; `unknown` when unavailable |
| `cpuMhz` | float64 | CPU clock speed (MHz); `0` when unavailable |
| `diskUsed` | float64 | Used space (GB) |
| `diskFree` | float64 | Free space (GB) |
| `diskTotal` | float64 | Total space (GB) |
| `diskUsedPercent` | float64 | Usage percentage (`0`–`100`) |

Note the letter casing of the field names: `goARCH` (all-caps ARCH), `cpuMhz` (lowercase `hz`), `numCPU`.

Disk statistics target the partition containing the project directory; `server/info` measures the partition containing the executable.

### Example

```json
[
  {
    "os": "linux",
    "platform": "Ubuntu 24.04.1 LTS",
    "goARCH": "amd64",
    "version": "go1.25.0",
    "numCPU": 8,
    "cpuName": "Intel(R) Xeon(R) Platinum 8269CY CPU @ 2.50GHz",
    "cpuMhz": 2500,
    "diskUsed": 452.12,
    "diskFree": 150.86,
    "diskTotal": 602.98,
    "diskUsedPercent": 74.98
  }
]
```

## Release manifest

Not a database entity and with no corresponding ent schema. It is a JSON file written to disk at publish time:

- Path: `data/{projectName}/.updator_manifest.json`
- Written after `publish_version` succeeds (temp file + `rename` atomic write)
- Served through `get_release_manifest`

```json
{
  "files": ["app.exe", "lib/core.dll", "config/app.json"]
}
```

| Field | Type | Description |
| --- | --- | --- |
| `files` | string[] | Set of file paths relative to the project at publish time, `/`-separated and sorted |

**Only one field, `files`**: it contains no sizes, hashes, version number, or time. Call `get_all_files` when you need that information.

The manifest's filtering rules are exactly the same as `get_all_files`:

- Skip `.chunks` / `.merging` upload intermediates;
- Apply the project's `ignore_folders` / `ignore_files`;
- Exclude the manifest itself, `.updator_manifest.json`.

Contract behavior:

| Scenario | `get_release_manifest` returns |
| --- | --- |
| Published normally | The path set at publish time |
| Never published | `{"files": []}`, `isSuccess: true` |
| Project missing / directory missing | `{"files": []}`, `isSuccess: true` |
| Manifest file corrupted | `isSuccess: false`, with `errorMsg` set to the JSON parse error |

## Time fields

| Field | Format | Example |
| --- | --- | --- |
| `created_at` (Project / ProjectChangeLog) | RFC 3339, nanosecond precision, local time-zone offset | `2026-11-10T10:59:35.6148004+08:00` |
| `lastUpdateTime` (FileInfo) | Same as above, taken from the file mtime | `2026-11-10T11:00:09.4428015+08:00` |
| `time` (ProjectChangeLog) | `yyyy-MM-dd HH:mm:ss`, a string supplied by the publisher | `2026-11-10 11:00:00` |

- The server does not convert time zones: `created_at` uses the server's local zone, and `time` stores the value the publisher gave verbatim.
- `time` may be empty; when non-empty it must parse as `yyyy-MM-dd HH:mm:ss`, otherwise the publish is rejected.
- Clients compare versions using the `version` field, not time; which version is newer is decided by `CompareVersion` (see [Publish Version](/en/docs/server/api-project#version-number-rules)).

## Entity relationships

```text
projects
├── id            (PK)
├── name          (UNIQUE)
└── version
      │ 1
      │
      │ N
project_change_logs
├── id            (PK)
├── project_id    (FK → projects.id, ON DELETE SET NULL)
├── version
└── logs
```

- Both tables have `is_deleted`, filtered as needed at query time: `get_all_projects` filters it, `get_project_by_name` does not.
- The server never physically deletes any rows; `ON DELETE SET NULL` is only protection at the foreign-key-definition level.
- Table structure and column changes are auto-migrated by ent at startup; the old database's `project_id` column is filled in by a one-time migration (see [Deployment](/en/docs/server/deploy)).
