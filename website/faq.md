# FAQ

## 为什么还要支持 Windows XP？

很多生产环境（工控上位机、收银终端、医院设备）仍在运行 XP，这些机器上的应用恰恰最需要安全地更新。主流更新框架（Squirrel、Velopack、Electron updater）都要求 Windows 7+，Aly 通过锁定 Go 1.10.8 + 386 工具链保留了这条通道，并且 CI 自动校验产物的 XP 兼容性（PE 头 + manifest）。

## 客户端宿主必须用 C# 吗？

不需要。`aly-client` 是独立可执行文件，所有命令输出统一的 stdout JSON 协议（`{"isSuccess", "errorMsg", "data"}`），任何能拉起子进程并解析 JSON 的语言都能做宿主。C# SDK 只是省掉编排工作的可选件。

## 更新时应用会停机多久？

`apply_update` 的停机窗口只有**三次目录改名**，秒级。因为下载阶段就把未变化的文件物化进了新版本目录（此时应用还在运行），应用阶段不需要复制任何文件。GB 级目录同样秒级完成。

## 更新到一半断电会怎样？

不会怎样。所有替换都是纯目录改名 + `version.json` 状态机守卫：下次启动时更新器检测到 `applying` 状态会重新执行改名步骤；已下载的包在应用前会校验完整性（文件数、内容版本），不完整则自愈并重新下载。见[核心概念](/guide/concepts#崩溃恢复)。

## 更新器自己怎么更新？

通过 `self_update` 命令的统一执行入口：新版本更新器随版本包进入主程序目录，GUI/SDK 启动时委派更新器本体执行替换（取锁、SHA256 比对、`.new` 中转、失败回滚、30 分钟窗口连续失败 3 次自动熔断）。详见[自更新设计](/advanced/self-update)。

## 回滚需要联网吗？

不需要。`rollback` 使用本地的版本快照目录（`ApplicationFolder_V1.0.0/`），纯本地改名操作。快照数量由 `clean --keep N` 控制。

## 服务端有认证吗？

当前版本设计为部署在**受信内网**，API 未内置认证与签名。若需公网暴露，请在前置网关做认证。见[服务端 API · 安全性说明](/reference/api#安全性说明)。

## 支持增量更新吗？

支持。发布端只上传与上一版本有差异的文件，客户端只下载与本地不同的文件（MD5+SHA256 比对），大文件走分片上传且断点续传。单文件下载失败不中断整体，重试只补失败文件。

## Linux GUI 需要装什么依赖？

只依赖桌面发行版预装的 GTK3 运行库。UI 库 MyGo 是纯 Go 实现（无 cgo），产物是单个 ELF 文件，amd64/arm64 交叉编译直接生效。无图形环境的机器仍可运行 `-finish-self-update` 收尾模式（不依赖 GTK）。

## 如何迁移或更换服务端地址？

改 `server_url` 后重新发布即可：`.updator/shared.json` 随版本分发，客户端下载更新时自动用新配置替换旧配置。
