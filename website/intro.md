# 项目简介

Aly 是一套**自包含的桌面应用自动更新系统**：发布方用一条命令把新版本推上服务端，用户机器上的更新器以崩溃安全的原子替换完成升级。它不依赖任何第三方更新框架，全部组件（服务端、发布工具、更新器、GUI、SDK）都在这一个仓库里。

## 解决什么问题

桌面应用发版经常面临的四个难题，Aly 给出的答案：

| 难题 | Aly 的做法 |
|---|---|
| 老机器更新不了 | 更新器锁定 Go 1.10.8 + 386 工具链，**Windows XP 可直接运行**；CI 自动校验产物 PE 头 |
| 更新过程断电/崩溃变砖 | 纯目录改名 + 版本状态机，启动时自动检测 `applying` 状态并恢复 |
| 大文件更新停机太久 | 下载阶段物化未变化文件，应用阶段只做三次 rename，停机窗口秒级 |
| 更新器自身怎么更新 | `self_update` 命令 + GUI/SDK 委派执行 + 失败计数防循环，闭环在仓库内解决 |

## 五个组件

| 组件 | 角色 | 技术栈 |
|---|---|---|
| **aly-server** | 存储项目元数据与文件，提供 REST API | Go 1.25 · Gin · Ent · SQLite |
| **aly-publish** | 发布命令行工具：初始化配置、扫描差异、暂存、推送 | Go 1.25 · cobra |
| **aly-publish-gui** | 桌面发布器（包装 publish-cli），面向非技术发布人员 | Avalonia 11.3 · .NET 8 |
| **aly-client** | 更新器本体，运行在终端用户机器上 | Go 1.10.8（XP 轨）/ 现代 Go（跨平台轨） |
| **aly-client-ui** | 可选 GUI 前端：屏幕右下角置顶窗口，按需显示 | Windows：walk（XP）· Linux：MyGo + GTK3 |

宿主程序通过两种方式使用更新器：直接拉起 `aly-client` 子进程解析 stdout JSON，或集成 [C# SDK](/docs/sdk)（自动编排检查、下载、应用、自更新全流程）。

## 设计原则

- **单文件、零依赖**：更新器与 GUI 都是单个可执行文件，目标机器拷过去就能跑，不需要安装运行库（Linux GUI 仅依赖桌面发行版预装的 GTK3）。
- **协议先于实现**：所有命令输出统一为 `{"isSuccess": bool, "errorMsg": string, "data": ...}`，GUI、SDK 与更新器解耦，任何语言都能做宿主。
- **配置即数据**：发布端与客户端共享 `.updator/shared.json`，且该配置随版本一起分发——服务端地址变更等配置调整会随下一次更新自动生效。
- **一切可验证**：下载内容 MD5 + SHA256 双校验；版本发布单调递增（服务端拒绝旧版本号回发）；[135 条端到端用例](/docs/testing)覆盖崩溃、断电、并发等恶劣场景。

## 适用场景

- 企业内网部署的桌面应用（工单系统、收银终端、工控上位机）——内网自托管服务端，无需公网。
- 包含大量 DLL/资源文件的 .NET / C++ 应用——目录级差异比对，只传变更文件。
- 必须支持 Windows XP / Windows 7 的遗留系统——这是绝大多数现代更新框架（Squirrel、Velopack、Electron updater）做不到的。
